# CRM Demo（顧客対応履歴管理）

顧客ごとの対応履歴を GUI で管理し、顧客名を引数に実行すると対応履歴を CSV で標準出力するデモ用アプリです。

- 配布物は **`dist\CrmDemo.exe` の1ファイルだけ**（約100KB）。インストール不要、DLL不要。
- Windows 10 / 11 に標準で入っている .NET Framework 4.8 で動くため、配布先に何も追加インストールする必要がありません。
- データは exe と同じフォルダの `crm_data.xml` に自動保存されます（書き込めない場所に置いた場合は `%LOCALAPPDATA%\CrmDemo\`）。

## GUI の機能

| 画面 | できること |
|---|---|
| 顧客・対応履歴 | 顧客の登録・編集・削除、顧客ごとの対応履歴（対応日／問い合わせ内容／対応内容／次回確認内容／次回確認日／担当者／完了）の追加・編集・削除、詳細表示 |
| 検索 | 顧客名・会社名・電話番号（ハイフン有無を問わない）・メール・履歴内容で絞り込み |
| フォローアップ | 未完了の「次回確認」を期限順に一覧表示。期限切れは赤、3日以内は黄色。ダブルクリックでその顧客の履歴へ移動 |
| 連携CSV出力プレビュー | 選択中の顧客名で exe を実行したときの標準出力を画面で確認・コピー |
| インポート | CSVファイル、Excelからコピーしたタブ区切りテキストの貼り付け、直接入力に対応。取り込み前にプレビューと行ごとの判定（新規顧客／既存顧客／重複／エラー）を表示 |
| エクスポート | 顧客一覧・全対応履歴・選択顧客の履歴を CSV（Excelでそのまま開けるBOM付きUTF-8）で保存 |
| 表示 | ライトモード／ダークモード／Windows の設定に合わせる（`Ctrl+Shift+L` またはステータスバーのクリックで切り替え。設定は保存されます） |
| データ管理 | サンプルデータ投入、バックアップ作成、データフォルダを開く、全削除（自動バックアップ付き） |

主なショートカット: `Ctrl+N` 新規顧客 / `Ctrl+T` 対応を追加 / `Ctrl+F` 検索 / `Ctrl+I` インポート / `Ctrl+P` 連携CSV出力プレビュー / `Ctrl+E` 全履歴エクスポート / `F5` 再読み込み / `F1` コマンドラインの使い方

## コマンドライン（他システム連携）

```
CrmDemo.exe "山田 太郎"
```

```
対応日,問い合わせ内容,対応内容,次回確認内容
2026/07/13,新システムの導入を検討中。製品資料を送ってほしい。,製品資料と価格表をメールで送付。,資料の確認状況をヒアリング
...
```

- 出力は対応日の古い順。1行目は見出し。カンマ・改行・`"` を含む項目は RFC 4180 形式で `"..."` で囲みます。
- 該当なしの場合は `該当する情報がありません` を出力します。
- オプションなしの引数は顧客名として扱います（`"山田 太郎"` と `山田 太郎` は同じ）。

### 検索条件（顧客名・会社名・電話番号・いずれか）

| オプション | 対象 | 照合ルール |
|---|---|---|
| `-n, --name <値>` | 顧客名 | 完全一致（`--partial` で部分一致） |
| `-c, --company <値>` | 会社名 | 部分一致。`株式会社`・`(株)`・`有限会社` などの法人格は無視（`サンプル商事` → `株式会社サンプル商事`） |
| `-t, --phone <値>` | 電話番号 | 数字だけで比較（ハイフン・全角・`+81` を吸収）。10桁以上は全桁一致、4〜9桁は末尾一致（下4桁など） |
| `-a, --any <値>` | 上の3項目のどれか | どれか1つに一致すれば該当 |

- **同じ項目内の複数値は OR**：`--name "山田太郎,佐藤花子"`（`,` `、` 区切り）や、同じオプションの繰り返しでも OR になります。
- **異なる項目どうしは AND**：`--name 佐藤花子 --company テスト工業` で同名の別人を絞り込みます。
- **項目が不確かなら `--any`**：`--any "山田太郎,サンプル商事,0312345678"` は、どれか1つでも一致した顧客を全員出力します。
- 空白・全角半角・大文字小文字の違いと、末尾の「様」「さん」は区別しません。
- 複数の顧客に該当しうる検索では `--full` を付けると、行ごとに顧客名・会社名が入り、要約側で誰の履歴か区別できます。
- GUI の［編集］→［連携検索テスト］（`Ctrl+Shift+P`）で、条件ごとの出力とコマンドをその場で確認できます。

### 音声テキスト連携での使い方の例

通話で聞き取れた項目だけ渡し、どの項目か判別できない値は `--any` に入れます。

```bash
CrmDemo.exe --any "山田太郎,サンプル商事,03-1234-5678" --full
```

- 名前の聞き間違いに備えたいときは `--any`（OR）を使います。
- 同姓同名を確実に分けたいときは `--name` と `--company` / `--phone` を組み合わせます（AND）。

### 対応履歴の登録（通話後の自動転記）

要約システムが作った「問い合わせ内容・対応内容・次回確認内容」を、顧客名・会社名・電話番号で特定した顧客の履歴として登録します。

```bash
CrmDemo.exe --add --name "山田 太郎" --phone 03-1234-5678 --inquiry "導入時期の相談" --response "来月初旬の導入で合意" --next "キックオフ資料の送付" --next-date 2026/09/18
```

| 状況 | 動作 | 終了コード |
|---|---|---|
| 顧客がちょうど1件に決まる | 対応履歴を登録（顧客の電話番号・会社名が空欄なら補完） | 0 |
| 同じ内容が登録済み | 二重登録しない | 0 |
| 該当なし | 登録しない（`--create` を付けると新規顧客を作って登録） | 1 |
| 複数該当 | 登録せず候補（顧客ID・顧客名・会社名・電話番号）を出力。`--id` で指定して再実行 | 2 |

- 顧客の特定には検索と同じ条件（`--name` / `--company` / `--phone` / `--any` / `--id`）を使います。自動転記では誤登録を防ぐため、`--name` と `--phone`（または `--company`）の組み合わせ（AND）をおすすめします。
- `--date`（既定は今日）、`--next-date`、`--staff`、`--done`（完了として登録）も指定できます。値の中の `\n` は改行になります。
- GUI を開いたままでも、登録した履歴は約1.5秒で画面に反映され、その顧客と履歴が自動で選択されます。

### その他のオプション

| オプション | 内容 |
|---|---|
| `-p, --partial` | 顧客名を部分一致で検索 |
| `-f, --full` | 顧客ID・顧客名・会社名・電話番号・メール・次回確認日・担当者・状態の列も出力 |
| `--no-header` | 見出し行を出力しない |
| `-e, --encoding <utf8\|utf8bom\|sjis>` | 標準出力・標準エラー出力の文字コード。パイプ／リダイレクト時の既定は BOM なし UTF-8（標準エラー出力には BOM を付けない） |
| `--all` | 全顧客の履歴を出力（`--full` 形式） |
| `--list` | 顧客一覧を出力 |
| `--import <ファイル>` | CSV を取り込む（バッチ投入用） |
| `--data <ファイル>` | データファイルを指定（環境変数 `CRM_DATA` でも指定可） |
| `--id <顧客ID>` | 顧客IDで指定（検索・登録で共通） |
| `--log <ファイル>` / `--no-log` | ログの保存先の指定 / ログを出力しない |
| `-h, --help` | ヘルプ |

### 標準入出力と終了コード（連携時の判定）

結果は**標準出力**、エラーは**標準エラー出力**に分けて出します。標準出力にエラーメッセージが混ざることはないので、標準出力をそのまま要約処理に渡せます。

| 状況 | 標準出力 | 標準エラー出力 | 終了コード |
|---|---|---|---|
| 検索：該当あり | 対応履歴のCSV（1行目は見出し） | なし | `0` |
| 検索：該当なし | `該当する情報がありません` の1行のみ | なし | `1` |
| 登録：成功 | `登録しました（顧客ID:1 山田 太郎（株式会社サンプル商事）、対応履歴ID:21、対応日:2026/09/11）` | なし | `0` |
| 登録：同じ内容が登録済み | `同じ内容の対応履歴が登録済みのため、登録しませんでした（顧客ID:1 …）` | なし | `0` |
| 登録：該当なし | `該当する顧客がいません（--create を付けると新規顧客として登録します）` | なし | `1` |
| 登録：複数該当 | 1行目にメッセージ、2行目以降に候補の `顧客ID,顧客名,会社名,電話番号` のCSV | なし | `2` |
| エラー（オプションの誤りなど） | なし | `エラー: 不明なオプション: --foo（--help で使い方を表示）` | `9` |

**該当結果がない場合（検索）**

```console
> CrmDemo.exe 存在しない人
該当する情報がありません
```

- 見出し行は出ません。`--full` を付けても、この1行だけです。
- **顧客は見つかったが対応履歴が1件もない場合**も、同じ出力・同じ終了コード `1` になります。
- 出力の末尾は改行（CRLF）です。

**複数該当（登録）のときの標準出力**

```console
> CrmDemo.exe --add --name 佐藤花子 --inquiry ... --response ...
該当する顧客が複数います。--id か条件の追加で1件に絞ってください
顧客ID,顧客名,会社名,電話番号
2,佐藤 花子,有限会社テスト工業,06-2345-6789
3,佐藤 花子,みらいデザイン株式会社,045-111-2222
```

この候補を使って `--id 2` のように指定し直すと登録できます。

**連携側の判定**

文字列ではなく**終了コード**で判定してください（メッセージの文言は変わる可能性があります）。

| 終了コード | 連携側の扱い |
|---|---|
| `0` | 標準出力をそのまま利用（検索ならCSVを要約へ、登録なら完了） |
| `1` | 「過去の対応履歴はありません」として扱う。登録時は新規顧客として登録するか運用で判断 |
| `2` | 顧客を特定できなかったため、オペレーターに確認を促す |
| `9` | 連携の設定ミス。標準エラー出力の内容をログに記録 |

### 文字コード（標準入出力）

パイプ・リダイレクトで受け取るときの既定は、標準出力・標準エラー出力ともに **BOMなしUTF-8** です。`-e` で変更できます。

| 指定 | 標準出力 | 標準エラー出力 |
|---|---|---|
| なし（既定） | BOMなしUTF-8 | BOMなしUTF-8 |
| `-e utf8bom` | BOM付きUTF-8（Excelでそのまま開ける） | BOMなしUTF-8（BOMは付けません） |
| `-e sjis` | Shift_JIS | Shift_JIS |

画面に直接表示するときは、コンソールの文字コードで表示します（`-e` の指定があればそれに従います）。

**Python（推奨）** — 既定のUTF-8のまま受け取ります。

```python
import subprocess
r = subprocess.run([r"C:\path\to\CrmDemo.exe", "山田太郎", "--full"],
                   capture_output=True, encoding="utf-8")
if r.returncode == 0:
    history_csv = r.stdout        # 要約処理へ渡す
elif r.returncode == 1:
    history_csv = None            # 対応履歴なし
else:
    raise RuntimeError(r.stderr)  # 2=複数該当 / 9=エラー
```

**Windows PowerShell 5.1** — 変数で受け取るときは `-e sjis` を付けると文字化けしません。

```powershell
$csv = & .\CrmDemo.exe 山田太郎 -e sjis
```

UTF-8のまま受け取りたい場合は、受け取る前に次を実行します。

```powershell
[Console]::OutputEncoding = [Text.Encoding]::UTF8
```

**PowerShell 7 以降** — 既定でUTF-8として扱われるため、そのまま受け取れます。

**コマンドプロンプト（cmd）** — 画面表示は `chcp 65001` でUTF-8にします。ファイルへ保存する場合は次のようにします。

```bash
CrmDemo.exe 山田太郎 > history.csv
```

保存したCSVをExcelで開くなら、`-e utf8bom` を付けるとそのまま開けます。

```bash
CrmDemo.exe 山田太郎 -e utf8bom > history.csv
```

**標準エラー出力も記録する場合**

```bash
CrmDemo.exe 山田太郎 > history.csv 2> error.log
```

標準出力と標準エラー出力を同じファイルにまとめると、CSVにエラー文が混ざるので分けてください。連携システム側で標準エラー出力を読むときは、標準出力と同じ文字コード（既定はUTF-8）で読んでください。Shift_JISとして読むと文字化けします。

### ログ

コマンドラインで実行するたびに、データファイルと同じフォルダの `crm_log.txt` に1行ずつ追記します（タブ区切り・UTF-8）。GUI の［ヘルプ］→［実行ログを開く］でも開けます。

```text
日時	処理	終了コード	処理時間	結果	引数
2026-09-11 14:03:22.418	search	exit=0	52ms	該当顧客 1 件・対応履歴 4 件：山田 太郎（株式会社サンプル商事）	--any "山田太郎,0312345678" --full
2026-09-11 14:10:05.031	add	exit=0	61ms	登録しました（顧客ID:1 山田 太郎（株式会社サンプル商事）、対応履歴ID:21、対応日:2026/09/11）	--add --name 山田太郎 ...
2026-09-11 14:12:40.776	search	exit=1	40ms	該当顧客 0 件・対応履歴 0 件（該当なし）	--name 存在しない人
```

- 処理: `search`（検索）/ `add`（登録）/ `list` / `all` / `import`。エラーのときは結果欄に `エラー: …` が入ります。
- 引数は1つ80文字までに省略し、改行は `\n` で記録します。
- 保存先は `--log <ファイル>` か環境変数 `CRM_LOG` で変更、`--no-log` か `CRM_LOG=off` で出力を止められます。
- 5MB を超えると `crm_log.1.txt` に切り替えます。ログが書けなくても検索・登録の結果には影響しません。

## インポート形式

1行目が見出しなら列名で自動判別します（順不同、不要な列は無視）。

`顧客名, 会社名, 電話番号, メール, 住所, 備考, 対応日, 問い合わせ内容, 対応内容, 次回確認内容, 次回確認日, 担当者, 状態`

（「お客様名」「電話」「問合せ内容」なども同じ列として認識します）

- 見出しがない場合は `顧客名,会社名,電話番号,メール,対応日,問い合わせ内容,対応内容,次回確認内容` の順とみなします。
- 先頭列が日付で見出しがない場合（このアプリの標準出力と同じ形）は、GUIで選択中の顧客に取り込めます。
- 同じ「顧客名＋会社名」は同じ顧客として履歴を追加します。既存顧客の空欄の項目だけを補完し、入力済みの値は上書きしません。
- 同じ顧客・対応日・問い合わせ内容・対応内容の履歴は重複としてスキップするので、同じファイルを何度取り込んでも安全です。
- 文字コードは UTF-8（BOM有無）／Shift_JIS／UTF-16 を自動判別します。

## ビルド

```
build.bat
```

Windows 標準の C# コンパイラ（`%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`）を使うので、Visual Studio や .NET SDK は不要です。成果物は `dist\CrmDemo.exe`。

## 補足

- コマンドラインから標準出力を確実に受け取れるよう、コンソールアプリとしてビルドしています。エクスプローラーからダブルクリックで起動したときは、黒い画面が一瞬表示されてすぐ消えます。
- データを保存するたびに直前の版を `crm_data.xml.bak` に残します。
- 対象は Windows 限定です（Mac/Linux は非対応）。
